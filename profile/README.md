## About the course

Data structures are organized ways of storing and accessing data in memory, chosen to match the demands of a specific task. Algorithms are step-by-step procedures for solving problems, evaluated by how fast and how much memory they consume. Together, they form the core analytical and design toolkit of computer science.

| CO | Course Outcome |
|:--:|----------------|
| **CO1** | Implement linear data structures with foundational sorting algorithms. |
| **CO2** | Apply stack and queue structures to solve sequential processing problems. |
| **CO3** | Build hash tables using appropriate hashing and collision strategies. |
| **CO4** | Implement binary tree and BST structures for hierarchical data management. |

## How pair work runs here

**Pairing.** You choose your own partner for each exercise. The one rule: **you may not pair with the same classmate twice** across Labs 3–8.

**Repository naming.** One private repository per pair per exercise:

```
LabExercise[NN]-[Surname]_[Firstname]-[Surname]_[Firstname]
```

Surnames in alphabetical order, diacritics removed (GitHub accepts only ASCII letters, digits, `.`, `-` and `_`). Example: `LabExercise05-Cruz_Maria-Pena_Jose` for Maria Cruz and José Peña.

**Deadline.** "Due: Week N — 5:00 PM" means the **laboratory day (Wednesday) of Week N**, 5:00 PM. The submission time is the **later** of the commit's author date and the time it was first pushed to GitHub. Commit *and push* before the deadline.

## How each partner is graded

A pair exercise has two independent measurements:

```
Lab Exercise grade  =  Submission score  ×  Contribution Score
```

The **submission score** is shared by both partners. The **Contribution Score** is individual and is read entirely from this organization's record — commits, issues, pull requests, reviews and comments. Everyone starts at 100%; deductions apply only where the record shows a gap.

| | What the record should show |
|---|---|
| **Code** | Your own share of the submitted code, by surviving lines in `git blame` |
| **Review** | At least one review of your partner's work with a written comment |
| **Planning** | At least one issue with a body, and at least one pull request with a description |
| **Communication** | Your own written explanation of the work, in the repository |

> **A repository where all commits come from one account will be treated as the work of one student.**
> A student with no commit, issue, pull request, review or comment of any kind receives **0** for that exercise.

AI and bot activity — including automated pull-request reviewers — is not counted as either partner's contribution.

## Getting started

1. **Accept the organization invitation** sent to your VSU address, `[student ID]@vsu.edu.ph`.
2. **Commit under your own account.** Set your git identity on every machine you use, so each commit is credited to you:

   ```bash
   git config --global user.name "Your Full Name"
   git config --global user.email "your-github-email@example.com"
   ```

   The email must be one registered on your GitHub account, or your commits will not link to your profile.
3. **Work in branches and pull requests.** Open an issue to plan, push your part on a branch, open a described pull request, and have your partner review it before merging.
4. **Never commit on your partner's behalf**, and never share an account or a laptop session that is signed in as someone else.
